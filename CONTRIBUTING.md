# Contributing & Collaboration

Thank you for your interest in **NIM Studio — Neuro Informatics Management Studio**.

NIM Studio aims to make routine research data organization accessible through local-first, reviewable desktop workflows. Contributions from researchers, clinicians, research software engineers, data stewards, and research infrastructure teams are welcome.

## Current project stage

The current repository contains publicly licensed project documentation and other materials. The NIM Studio application source code is planned for public release in **January 2027** under the proposed **Apache License 2.0**, subject to final release checks and rights confirmation.

Until the source is published, contributions can focus on documentation, reproducible example use cases, interoperability discussions, and beta feedback. There is no public application codebase to fork yet.

## Ways to contribute now

- **Documentation:** Correct unclear instructions, improve terminology, propose tutorials, or contribute synthetic examples.
- **Bug reports:** Describe reproducible issues with non-sensitive test data and the application version used.
- **Feature requests:** Explain the research task, the current obstacle, and what an improved workflow should enable.
- **Scientific collaboration:** Propose study or project package designs, governance use cases, user evaluations, or cross-institutional reproducibility studies.
- **Interoperability proposals:** Discuss potential connections with established ecosystems such as Nipoppy or Clinica. Pipeline launching is a future idea, not an implemented NIM Studio feature.

## How to contribute

1. **Documentation and examples:** Submit a focused pull request for corrections, tutorials, or synthetic examples. Explain the change and its intended use.
2. **Beta feedback:** Approved testers should report bugs and usability problems through their designated private beta-feedback channel.
3. **Feature ideas and collaboration:** Contact the maintainer through an established professional or project channel, describing the research problem, intended users, and proposed outcome.
4. **Substantial changes:** Agree on the scope of an integration or new workflow with the maintainer before beginning implementation.
5. **Application code:** Public source code is planned for January 2027. Development, testing, and code contribution instructions will accompany that release.

## Information to include

For a bug or usability report, include:
- NIM Studio version and operating system
- The relevant module and workflow stage
- Expected behavior and observed behavior
- Steps to reproduce using synthetic or safely de-identified data
- Sanitized error messages, if useful

For a collaboration proposal, include:
- Research goal and intended users
- Data modalities and the organizational challenge
- Relevant standards or tools
- Proposed outputs or evaluation criteria
- Whether the idea needs an integration, documentation, or study-design discussion

## Privacy and security

**Never publish identifiable participant data, clinical records, access tokens, credentials, private institutional paths, or confidential logs in public pull requests or other public channels.**

Use synthetic data for examples. Report security vulnerabilities privately through the official NIM Studio contact channel; do not post exploit details publicly.
